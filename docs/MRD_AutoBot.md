## 1. 执行摘要

**一句话定位**：AutoBot 是面向电竞俱乐部的 CS 拟真 AI 陪练系统 —— 通过「计算机视觉感知 + A* 路径规划 + 硬件级键鼠模拟」技术闭环，在俱乐部私有训练服务器上提供 7×24 小时、水平可配置、战术可编排的 AI 对手，按使用量订阅收费。

**核心论点**：

1. **痛点真实且付费意愿已验证**：电竞俱乐部的日常训练高度依赖真人陪练（青训队员、二队、约队），成本高、难调度、水平不稳定。我们与目标客户（俱乐部教练/负责人）完成了直接沟通并已获得付费客户，验证了「为可调度的拟真 AI 陪练付费」的需求真实性。
2. **技术闭环已跑通**：项目已完成最小可行产品（MVP）开发并交付使用 —— 视觉定位、阵营识别、自主导航、遭遇战斗、守点巡逻全链路闭环，不依赖游戏官方 API。
3. **合规路线清晰**：产品定位为私有训练服场景的陪练工具，不触碰官方匹配环境；硬件级输入模拟确保与训练服环境的兼容性。
4. **商业模式明确**：按使用量（训练时长 / 机器人数量）订阅计费，随客户训练规模自然扩张。

**融资目的**：将已验证的 MVP 升级为标准化、多地图、数据驱动的 SaaS 化产品，扩大付费俱乐部客户规模。

## 2. 市场背景与问题定义

### 2.1 行业背景

- **电竞产业持续增长**：全球电竞市场规模在 2024 年已达约 18~20 亿美元量级（Newzoo 等行业口径），中国电竞用户规模约 4~5 亿人，电竞俱乐部/战队的专业化、体系化训练投入逐年提升。
- **AI Agent 技术窗口**：2024 年之后，视觉识别（YOLO 系列）、路径规划、行为决策等 AI 能工程化成本大幅下降，使「拟真游戏 AI 陪练」从研究课题变为可商业交付的产品。
- **CS2 官方生态的空窗**：CS2 转型后官方内置 Bot 能力弱化且不拟真（行为脚本化、无战术变化），官方未提供面向第三方的训练 API，「高质量训练对手」存在明确供给缺口。

### 2.2 核心问题（客户视角）

| # | 问题 | 现状代价 |
|---|---|---|
| P1 | 真人陪练贵、难约、难调度 | 头部俱乐部依赖约队/青训陪练，单次训练协调成本高，时段覆盖率低 |
| P2 | 陪练水平不稳定、不拟真 | 官方 Bot 行为呆板，练不出实战反应；真人陪练强度参差，训练质量波动 |
| P3 | 特定战术无法反复演练 | 教练需要针对特定动线（如 A 区快攻、默认布防）做重复对抗训练，真人陪练难以无限重复且成本线性增长 |
| P4 | 训练数据缺失 | 陪练对抗缺少结构化数据记录（命中率、反应时间、动线热图），复盘靠人工看 Demo |

### 2.3 为什么现在（Why Now）

1. **AI 能力拐点**：轻量视觉模型（YOLOv8n/s 级）在消费级 GPU 上实时运行成熟，硬件成本可控。
2. **生态空窗**：CS2 官方 Bot 弱化 + 无开放训练 API，第三方拟真陪练无强竞品。
3. **已验证的先行优势**：我们已完成 MVP 交付并获得付费客户，具备数据与工程积累的先发窗口。

## 4. 目标客户与用户画像

### 4.1 付费决策者（Buyer）

**俱乐部经理 / 领队 / 教练**
- 关注训练质量与成本效率：陪练预算可视化、训练时段利用率
- 决策链短：技术型采购，试用见效快即可推进
- 采购形态：俱乐部级私有部署 + 按使用量订阅

### 4.2 日常使用者（User）

**主力队员 / 青训队员**
- 需要高水平、可调节强度的对抗环境保持状态、练特定点位攻防
- 期望 AI 行为拟真：会走位、会架点、会反击，而非脚本化 Bot

**教练**
- 需要可编排的战术脚本：让 AI 复现特定动线（RUSH、默认、回防路线），反复演练
- 需要训练数据报表支撑复盘与选材决策

### 4.3 典型使用场景

| 场景 | 描述 | 对应功能 |
|---|---|---|
| 日常保持性训练 | 队员非集体训练时段，与 AI 打对抗保持状态 | 拟真对抗、可配置难度 |
| 战术专项演练 | 教练设定「对方 A 区快攻」，全队反复练应对 | 战术动线配置 |
| 青训选材考核 | 标准化 AI 对抗环境，横向比较青训队员数据 | 数据报表 |
| 填充训练赛 | 凑不满 10 人时 AI 补位打训练赛 | 多 bot 协同 |

## 5. 竞争分析

| 竞争方向 | 代表 | 与 AutoBot 的差异 |
|---|---|---|
| 官方 Bot | CS2 内置 Bot | 行为脚本化、不拟真、不可编排战术、无数据输出；官方无训练 API 开放计划 |
| 真人陪练/约队 | 俱乐部青训、陪练平台 | 成本高、调度难、水平波动、不可无限重复；我们的核心替代对象 |
| Aim Trainer 类 | Aim Lab 等 | 只练枪法维度，无战术、无动线、无团队对抗场景，互补而非替代 |
| 学术/开源 Bot | 基于 Source 引擎 Mod 的 Bot 项目 | 依赖引擎修改/游戏内 API，与商业服务器的兼容性和维护成本是短板；我们走「外部视觉 + 硬件输入」路线，不依赖引擎内部接口 |

**核心壁垒**：

1. **全栈技术闭环**：视觉感知（截屏→识别）→ 决策（路径规划/战斗策略）→ 执行（硬件级 HID 键鼠模拟）的完整链路，各环节工程细节（定位稳定性、卡死恢复、运动校准）是长期踩坑积累。
2. **不依赖游戏 API**：以「外部观察者 + 硬件输入」方式运行，游戏版本迭代导致接口失效的风险显著低于引擎 Mod 类方案。
3. **数据飞轮**：付费客户训练数据（动线、对抗结果）持续回流，反哺 AI 行为拟真度，形成越用越强的正循环。

## 6. 产品定位与价值主张

**For** 电竞俱乐部与职业训练体系，
**Who** 需要高质量、可调度、可重复的 CS 对抗训练环境，
**AutoBot 是** 一个部署在私有训练服的拟真 AI 陪练系统，
**That** 以视觉感知与路径规划实现拟真对抗行为，以硬件级输入兼容训练环境，以战术编排和数据报表放大教练产出。
**Unlike** 官方 Bot 的脚本化行为或真人陪练的高成本调度，
**AutoBot** 提供 7×24 可用、强度可调、动线可编排、数据可沉淀的训练对手，按使用量付费。

**价值量化方向**（客户侧）：

- 陪练成本：AI 替代部分真人陪练时段 → 单位训练成本下降
- 训练覆盖率：非集体时段（夜间/休赛期）训练能力从 0 → 7×24
- 复盘效率：结构化数据报表替代人工看 Demo

## 8. 商业模式与定价

### 8.1 模式：按使用量订阅（Usage-based Subscription）

- **计量维度**：训练时长（小时）/ 训练局数 / 同时在线 Bot 数量，三选一或组合（以客户实测偏好为准，P0 阶段灰度验证）
- **形态**：俱乐部级基础订阅（含席位管理、数据报表）+ 超出套餐部分按量计费
- **硬件**：控制盒随订阅提供（押金/租赁），降低采用门槛，锁定续费

### 8.2 定价锚点逻辑

- **对标替代成本**：真人陪练综合成本（陪练人员时薪 + 协调成本）为价格上锚，AI 订阅定价为其 1/3~1/2，客户有明确 ROI 感
- **分层**：青训队/学院（入门档）→ 职业一线队（专业档）→ 训练工作室/平台（不限量档）
- 具体价格带在扩大客户验证后固化，MRD 不锁死数字

### 8.3 单位经济模型（框架）

收入 = 客户数 × 月均训练用量 × 单位价格；
成本 = 硬件摊销 + 部署运维 + 研发摊薄；
规模效应来源：硬件标准化降本、多 Bot 并行摊薄算力、数据飞轮降低拟真研发边际成本。

## 10. 风险分析与应对

| 风险 | 等级 | 应对策略 |
|---|---|---|
| **合规风险**：游戏厂商对第三方自动化工具的政策收紧 | 高 | 坚守私有训练服场景，不触碰官方匹配；与俱乐部共建合规使用规范；中期推动与赛事方/厂商的官方合作对话；产品宣传严格限定训练用途 |
| **技术风险**：游戏版本更新破坏视觉/标定体系 | 中 | 配置热更新 + 模型快速迭代双轨适配机制；72 小时适配 SLA；多定位方案冗余（HSV + ORB 特征匹配已有备份链路） |
| **市场风险**：厂商自研或开放官方训练 API | 中 | 先发数据壁垒 + 战术编排/复盘的教练工作流粘性；必要时转为官方生态服务商 |
| **竞争风险**：大厂/平台型玩家入场 | 中 | 深耕俱乐部直销关系与私有部署形态（大厂倾向云端通用方案），保持细分领先 |
| **交付风险**：多 Bot 协同与拟真度提升难度超预期 | 中 | P0 范围严格聚焦（不做开放世界级行为，只做训练场景动线拟真）；里程碑分阶段验收 |

## 13. 附录 A：MVP 技术架构速览

```
┌────────────────────────────────────────────────────┐
│                    主循环 (main.py)                 │
│  截屏(mss) → 定位/识别 → 校准 → 导航 → 战斗/守点      │
└────────────────────────────────────────────────────┘
感知层: PlayerLocator(HSV小地图定位+稳定器) / PlaceDetector+RoleDetector(YOLO双模型)
       MinimapMatcher(ORB特征匹配,备份链路)
决策层: Navigator(实时A*寻路+waypoint跟随) / CombatController(瞄准/开火/防误伤)
       SiteGuard(守点巡逻) / AntiStuck(卡死恢复) / MovementCalibrator(运动校准)
执行层: ArduinoController → 串口(9600bps) → Arduino Leonardo(USB HID键鼠模拟)
交互层: PyQt5 GUI控制台 / 6个标定工具 / Dry-run调试模式
```

**关键工程细节**（构成技术know-how）：
- 三级阵营识别兜底链：场景识别 → 出生点距离推断 → 人物检测
- 黑区位置真实恢复机制（不靠坐标吸附，强制走回可通行区）
- 队友挡线检测（几何线段-包围盒相交判定）防止训练赛误伤
- 运动学自校准：短脉冲探测测速 + 朝向估计，适应不同灵敏度设置
